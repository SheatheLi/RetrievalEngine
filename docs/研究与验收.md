# AI/ML｜量化上界与精确 Top-K 检索｜技术增强研究与验收

## 核心认知与真实问题

近似向量检索降低精排成本可能牺牲准确性；需要在结果正确性和计算预算之间提供可检测的边界，而不是假设固定 nprobe 足够。

**本阶段判断：** 这是有实际工作指向的研究切片，而不是已证明行业领先的旗舰成果。验证充分性要以专业生态的真实对象、成熟强基线和个人技术接管为准。

## 实际技术栈（运行平台／框架／基础设施）

PyTorch 双塔 Embedding、scikit-learn KMeans/PCA、NumPy、Python CPU 向量计算、按维标量量化、离线检索实验；Faiss 未集成。

## 专业机制与来源（不是技术栈的同义词）

量化向量近似内积、重建残差 L2 范数、柯西—施瓦茨上界、分支限界精确复核、稳定 Top-K 并列规则。

**参考来源或技术体系：** https://faiss.ai/；https://github.com/facebookresearch/faiss/wiki/Additive-quantizers；已有算法成熟，不能称开创性搜索。

研究方法中的已知算法不声明原创；移植和组合也只有在真实负载胜过成熟替代方案时才能被称为独立优势。

## 已实现结果及边界

公开手写数字的 PCA-24 检索代理（1,400 向量、397 查询）：量化残差上界分支限界 397/397 查询与穷举 Top-10 完全一致，平均约 11.04 次全精度候选打分，对比旧认证簇搜索约 972.82 次；但是每个查询仍有 1,400 次量化粗打分，Python 端计时约 0.080 s，对比向量化穷举约 0.034 s，反而更慢。

运行命令与逐项数据见 `evidence/增强对照.json`。代码中包含新增专项测试。原有基准是历史证据，不得混用不同源码版本。

## 强对照与失败结构

数据不是推荐交互；真实在线 serving/FAISS/PQ/HNSW/缓存与多机吞吐未完成；粗算和排序仍 O(nd)；内存中同时保存原始与重建向量；没有真实低延迟收益。

当前专业领域问题仍然未被完整攻克；如果迁移到真实系统后新方法不胜强基线，优先否决候选机制，不通过更多技术名词修饰。

## 下一步应攻克的高压课题（未实现，禁止作为当前简历事实）

采用真实用户—物品时序数据，在 Faiss IVF-PQ/HNSW、ScaNN 和 Exact Flat 间做 Recall/NDCG/P99/CPU/内存 Pareto；结合半精度误差预算、粗检索 TopK 边界与 GPU/AVX 加速。

## 工程化验收规则

- 真实对象：必须有可独立复现的上游机制问题、第三方真实数据或真实服务负载。
- 算法价值：比较成熟且相关的专业方法，而不是只比较自制弱方案。
- 量化：必须带分母、负载、环境、反例、消融、P95/P99 或效用与成本。
- 发布：可安装/构建、运行入口、干净环境测试，单项目根目录，不使用轮次编号组织。
- 求职：Target 与 Current 分开；未被本人追踪、修改、调试与答辩的技术不作为已掌握声明。

## 历史研究基线（仅供追溯，非当前成果）

# 研究与验收｜Multi-Stage Search & Recommendation Engine

## 问题重构
近似召回阶段遗漏的候选无法被下游排序恢复；向量检索速度与精确性、表示质量必须分开评估。 与其说“需要增加技术栈”，不如说需要进入真实运行时/模型/决策对象，比较成熟可行机制以及适用边界。

## 可核查原始动机
旧实验 300 查询 Top10 完全相同且自适应更慢；原合同要求时间切分、两塔/ANN/排序、检索 ceiling、真实数据和强基线。

## 参考成熟设计与外部问题
- FAISS practical benchmarks: https://github.com/facebookresearch/faiss
- ANN benchmark methodology: https://github.com/erikbern/ann-benchmarks
- Temporal recommender reference: https://github.com/frankhou42/two-tower-recommender

这些资料证明对应技术问题或技术方法存在；**本项目没有声称已复现上述所有 Issue，也不默认已有方案不足。**

## 技术竞争结构

- 强基线：选择本领域不用新机制的可用方法，在同一输入/任务下测量。
- 核心候选：按用户时间切分的隐式反馈双塔、采样负例损失、IVF 倒排聚类、以 Cauchy-Schwarz 上界证明未访问簇不可能进入 Top-K 的终止条件，并分别评估 ANN 近似损失与模型表示 ceiling。
- Oracle：独立正确性/模拟真值/精确检索/事务日志（随领域而异）；严禁将辅助 Oracle 泄露给真实预测决策。
- 否决规则：若候选输给同预算成熟方案、缺少真实价值、不能解释失败，必须 Pivot 或 Kill，不能只调简历文案。

## 已完成的实验与指标
合成时序交互 3 seeds：IVF ANN Recall@10 vs exact=0.629；certified bound=1.000（数学上界保证）。真实 digits 代理 397 查询：IVF=0.972、certified=1.000，平均计算 972.8/1400 项，非真实推荐收益。

## 不等价的声明
双塔训练用的是合成点击序列；公开手写数字仅提供检索索引的真实数据代理，不是在线推荐数据；没有 LightGBM ranker、FAISS 或真实服务 p99。

## 下一层高压技术与现实缺口
- 合规获取真实时间序列推荐数据（如 MIND），严格 train/validation/test 时序划分
- FAISS IVF/HNSW 与 certified bound 的同硬件精确成本测量
- 加上 LambdaMART 重排与负例挖掘，并量化候选 ceiling
- 长尾用户/冷启动/索引版本漂移分层评估
